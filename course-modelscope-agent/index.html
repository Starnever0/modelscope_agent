03

检索引擎：语义 + 关键词双保险

看懂混合检索与并行召回，你就能让 AI “找得准、找得快”。

像找书：图书馆检索 + 目录检索同时进行

FAISS 负责“语义相近”匹配，BM25 负责“关键词精确”匹配，然后用加权方式合并结果。

🧠
Aha: 混合检索的本质

单一策略总会有盲区。把“语义理解”和“关键词命中”组合，能更稳地覆盖不同提问习惯。

CODE 

return EnsembleRetriever(
    retrievers=[vector_retriever, bm25_retriever],
    weights=[0.5, 0.5]
)
PLAIN ENGLISH

返回一个“组合检索器”。

它同时使用向量检索器和 BM25 检索器。

两边权重都是 0.5，表示各占一半影响力。

最后输出融合后的候选文档。

05

稳定性设计：出错时系统怎么自救

真正可用的 AI 产品，不是“不出错”，而是“出错后能优雅恢复”。

像导航软件：走错路要自动重规划

router、grade、rewrite 形成了一个有界反馈环：先判读，再检索，不够好就重写一次。配合 兜底策略 与 降级，整体体验会稳定很多。

CODE 

try:
    analysis = router_chain.invoke({"messages": state["messages"]})
    return {
        "rewritten_query": analysis.standalone_query,
        "datasource": analysis.datasource
    }
except Exception as e:
    last_msg = state["messages"][-1].content
PLAIN ENGLISH

先按理想流程走：调用路由链做解析。

如果成功，返回独立查询和数据源选择。

如果失败，不让系统崩掉，而是抓取用户最后一句做保底。

这是典型“先最优，后保活”的工程心法。

实战指挥手册：如何用这些知识驾驭 AI

把“看懂代码”转化为“能下高质量指令”。

像带团队：你不亲自写，但要会下清晰指令

当你知道 thread_id、路由、检索、重排、生成这些环节，就能把模糊需求改写成精确任务："在 router 加一个 chat 快速通道"，而不是“帮我优化一下”。

模块边界告诉 AI 逻辑应该放在哪个文件或节点
失败路径要求 AI 明确异常分支与降级策略
验证命令要求 AI 给出可执行验证步骤，而不只说“应该可以”
CODE 

def route_after_decompose(state: RagState) -> str:
    if state["sub_questions"] is not None:
        return "parallel_retrieve_node"
    return "retrieve_docs_node"
PLAIN ENGLISH

定义一个“分解之后怎么走”的决策函数。

如果已经拆出子问题，就走并行检索路径。

否则走普通检索路径。

这是把业务复杂度翻译成流程分支的典型写法。
